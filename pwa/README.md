# Веб-версия Mood (PWA)

Приложение Mood в браузере: ставится на домашний экран телефона и открывается
оттуда в режиме standalone, без адресной строки, с офлайн-оболочкой и последним
загруженным расписанием.

Код интерфейса целиком лежит в `pwa/src` — страницы, компоненты, дизайн-система и
клиент API. Отдельной копии интерфейса и второй сборки больше нет, поэтому
изменение страницы попадает в приложение сразу и правки не расходятся.

---

## Как это работает

Приложение самостоятельное: оно открывается из браузера и с домашнего экрана, то
есть **вне Telegram**, где подписи `initData` не существует вовсе. Поэтому вход
свой — логином и паролем от личного кабинета БАРС:

1. На экране входа человек вводит логин и пароль БАРС.
2. `POST /api/auth/login` (или `/register` для первого входа) проверяет их по
  -настоящему, через живой БАРС.
3. Если БАРС прислал код подтверждения — ответ `401 need_2fa` с `challengeId`,
   и человек вводит код на втором шаге (`POST /api/auth/2fa`).
4. Сервер отдаёт токен на 90 дней; он кладётся в `localStorage` и едет в каждом
   запросе заголовком `X-PWA-Token`.

Оба клиента — бот и PWA — обслуживают **одну и ту же запись** пользователя.
Ключ связи — `barsLoginHash` (sha256 от нормализованного логина БАРС) в
`data/users.json`:

- человек вошёл сначала в бота, потом в PWA → тот же `userId`, общие ДЗ;
- человек вошёл сначала в PWA, потом в бота → тот же `userId`, общие ДЗ;
- привязка Telegram не блокирует PWA: оба клиента могут работать с одной записью.

Токен **не расширяет доступ**: он подставляет того же пользователя и ту же запись
из `userStore`. Проверки `requireBars`, `requireStudentGroup` и изоляция по
группам в `routes/files.ts` работают без единой правки.

На сервере проверяется не только подпись токена, но и его **хэш в `pwaTokens`
пользователя** (см. `backend/server/middleware/auth.ts`): без этого подписи было бы
достаточно, чтобы выпустить токен с произвольным `userId` и сроком на 90 дней.

**Срок жизни токена — 90 дней** (`PWA_TOKEN_TTL_MS`). Когда он истечёт, PWA
покажет экран входа; продлить можно тем же входом по логину БАРС.

### Переменные окружения

| Переменная | Обязательна | Что делает |
|---|---|---|
| `PWA_AUTH_SECRET` | для PWA | 64 hex-символа (32 байта). Секрет подписи токенов. Отдельный от `ENCRYPTION_SECRET_KEY`: утечка одного не даёт возможности подделать другой, а ротация одного не выкидывает всех из приложения |
| `PWA_URL` | для кнопки в боте | Публичный HTTPS-адрес PWA. Не задан — кнопки «Открыть в браузере» не будет |

Обе генерируются/дописываются командой `npm run pwa:setup`. Секрет в git не
попадает: `.env` в `.gitignore`.

## Локальная проверка за 10 шагов

```
1. npm run pwa:setup                    — секрет, зависимости, иконки, сборка
2. Терминал 1: npm run dev              — бот + API на 127.0.0.1:3000
3. Терминал 2: npm run pwa:dev          — vite на 127.0.0.1:5173
4. Открыть http://127.0.0.1:5173 в Chrome
5. Увидеть экран входа и войти логином и паролем БАРС МЭИ
   (если аккаунта в приложении ещё нет — та же кнопка «Создать аккаунт»;
    Telegram для входа не нужен)
6. Проверить базовое: расписание грузится, свайп недель работает, вкладки
   переключаются, данные БАРС/почты подтягиваются
7. Lighthouse (DevTools → Lighthouse → категория PWA):
   - все проверки зелёные, кроме HTTPS (для localhost это норма)
   - «Installable» должен быть true
8. npm run pwa:build && cd pwa && npm run preview   — собранная версия на :4173
9. Проверить офлайн: DevTools → Network → Offline → перезагрузить
   - должна открыться оболочка
   - расписание из кэша показывается
   - вкладки «Оценки», «Задания» показывают свой ErrorState (это правильно)
10. npm run lint && npm run test:all — типы и тесты проходят
```

Про Service Worker в dev: он **не регистрируется** (`import.meta.env.DEV`), иначе
кэш ломал бы hot-reload и разработчик видел бы старый код. Офлайн проверяется
только на собранной версии — на шаге 8 и 9.

### Обратная связь с ботом

Вход в PWA не требует Telegram, поэтому и кнопки dev-входа нет: она была бы
обходом единственной настоящей проверки учётных данных, а проверять тут нечего.
Локальная разработка запускается как обычно:

```bash
# Терминал 1 — бот и API в режиме разработки:
npm run dev

# Терминал 2 — фронтенд:
npm run pwa:dev
```

Готовая связка «туннель + бот + vite» — `bash pwa/scripts/dev-tunnel.sh`, см. ниже.

## Проверка на iPhone

iPhone не поставит PWA с `http://localhost` и не покажет кнопку установки вне
HTTPS. Нужен туннель:

```
npm run pwa:dev:test
→ дождись строки "PWA доступен: https://xxx.trycloudflare.com"
→ открой этот адрес в Safari на iPhone
→ Поделиться → На экран Домой
→ запусти с домашнего экрана
→ убедись, что открывается в полноэкранном режиме, показывает расписание,
  и что при переключении в авиарежим последнее расписание всё ещё видно
```

Сценарий A (по умолчанию) — **один туннель на vite**, vite проксирует `/api` на
`:3000`. Проще всего, CORS не участвует, `PWA_URL` совпадает с адресом туннеля.

Сценарий B — два туннеля, фронт и API отдельно. Нужен, чтобы проверить
кросс-доменное поведение CORS в проде: поднять второй туннель на `:3000`,
переменную `API_ORIGIN`/`VITE_API_TARGET` направить на него, а `PWA_URL`
оставить на туннель фронта. Тогда origin'ы разойдутся, и запрос пойдёт через
CORS — именно этот путь проверяет `allowedOrigins()` в `backend/server/index.ts`.

### Установка на iPhone: пошагово

Safari на iPhone **не** показывает кнопку установки — только меню «Поделиться».
Это главная причина, по которой люди думают, что установка невозможна.

1. Открыть адрес PWA в **Safari** (не в Chrome — в Chrome будет свой, другой PWA).
2. Нажать кнопку **«Поделиться»** — квадрат со стрелкой вверх, внизу экрана.
3. В списке пролистать вниз до **«На экран Домой»**.
4. Проверить имя (по умолчанию «Mood») и нажать **«Добавить»**.
5. Запустить с домашнего экрана: иконка, без адресной строки.

Android Chrome: меню ⋮ → «Установить приложение» → «Установить».

## Сборка и деплой

```bash
npm run pwa:build          # иконки + tsc --noEmit + vite build + версия в sw.js
cd pwa && npm run preview  # посмотреть собранную версию на :4173
```

### Вариант A — всё на VPS за nginx (рекомендуется)

```bash
sudo mkdir -p /var/www/mood-pwa
# ВАЖНО: rsync, а не `cp -r dist/*`. Манифест сборки лежит в pwa/dist/.vite/
# и скрыт от `*`, поэтому обычным копированием он на сервер не попадает.
sudo rsync -a --delete pwa/dist/ /var/www/mood-pwa/
sudo cp pwa/nginx.conf.example /etc/nginx/sites-available/mood-pwa
sudo ln -s /etc/nginx/sites-available/mood-pwa /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d pwa.example.com
```

Проверка, что статика легла целиком:

```bash
curl -sI https://pwa.example.com/.vite/manifest.json | head -1   # ожидается 200
```

Если здесь 404 или приходит `index.html`, офлайн-оболочка Service Worker собрана
без бандлов, и на холодном запуске установленного приложения при слабой сети
вместо приложения откроется белый экран.

В `.env`:

```env
PWA_URL=https://pwa.example.com
```

Перезапуск бота: `npm run build && systemctl restart mood`.

Важные моменты конфига (подробности и комментарии — в самом файле):

- `location = /sw.js` с `Cache-Control: no-cache` — без этого браузер месяц не
  увидит новый Service Worker;
- `/api/` с `proxy_read_timeout 120s` — `/api/mail` и `/api/bars/grades` ходят
  в OWA и БАРС и живут дольше стандартных 60 с;
- `/assets/` с `expires 1y immutable` — имена хешированные, кэш безопасен;
- `index.html` без кэша — иначе после деплоя откроется старый бандл.

### Вариант B — фронт на Vercel/Cloudflare Pages, API на VPS

1. `pwa/dist` задеплоить как статику (build command `npm run build`, output
   `dist`, root directory `pwa`).
2. `/api` на этой платформе **не проксируется** — либо настроить rewrite на
   `https://api.example.com/api/:path*`, либо (правильнее) оставить API на
   отдельном домене и полагаться на CORS.
3. В `.env` на VPS:

   ```env
   PWA_URL=https://pwa.vercel.app
   API_ORIGIN=https://api.example.com
   ```

4. `PWA_URL` добавляется в CORS автоматически — отдельных правок в коде не
   нужно (см. `allowedOrigins()` в `backend/server/index.ts`).

Проверить, что origin действительно в белом списке: запрос с чужого `Origin`
должен вернуться без `Access-Control-Allow-Origin`.

## Офлайн: что кэшируется, а что нет

| Запрос | Стратегия | Почему |
|---|---|---|
| `/` и оболочка, `/assets/*`, `/icons/*` | cache-first | Хешированные имена, «старая» копия всегда верна для своей версии |
| навигация (`mode: 'navigate'`) | network-first → оболочка → `/offline.html` | Новая сборка подхватывается сразу; без сети лучше приложение с вчерашним расписанием, чем заглушка |
| `/api/schedule` | stale-while-revalidate | Расписание меняется раз в сутки: вчерашнее мгновенно лучше, чем ожидание сети. Хранится последние 3 диапазона |
| `/api/bootstrap` | network-first, таймаут 3 с | От него зависит само открытие приложения |
| `/api/bars/**`, `/api/mail`, `/api/homework`, `/api/important` | network-only | Слишком динамичны и слишком личны: вчерашние оценки завтра будут враньём, которое студент не отличит от правды. `/api/mail` к тому же под 30-секундным кулдауном |
| `/api/auth/**`, `/health`, `sw.js` | никогда | Первые два — пароль от БАРС и служебный ответ, третий — сам механизм обновления |
| POST/PATCH/DELETE | никогда | Любая мутация уходит в сеть целиком |

Версия кэша — метка сборки, подставляется в `sw.js` скриптом
`scripts/inject-sw-version.mjs`. Сменилась версия — имена кэшей другие, старые
удаляются в `activate`.

## Встроенный просмотрщик фото (InAppBrowser)

Тап по картинке в задании или объявлении открывает вкладку внутри приложения —
`src/components/InAppBrowser.tsx`. Тап по любому другому файлу (pdf, doc/docx,
zip, …) встроенно НЕ открывается, а сразу отдаётся системе как при «Скачать»
(системный шит «Поделиться» с файлом, иначе сохранение) — у нативного
просмотрщика в webview есть свой тулбар, который не убрать (`#toolbar=0` не
работает), а из установленного PWA в Safari программно не выйти. Отдельной
кнопки «Скачать» в строке файла нет: тап уже скачивает.

Вёрстка вьюера фото: крестик закрытия, название файла по центру и одна кнопка
действия — системный шит «Поделиться» с файлом. Псевдо-адреса и копирования
ссылки больше нет. Сам просмотр (зум, свайп по соседям, закрытие свайпом вниз)
не менялся. Шапка опущена ниже кромки экрана (свой отступ поверх
`safe-area-inset-top`), чтобы кнопки были ближе к большому пальцу.

Масштабирование интерфейса щипком запрещено (viewport `maximum-scale=1,
user-scalable=no` + гашение iOS-жестов в `lib/env.ts`), кроме самого вьюера.

### Что сделано ради скорости и памяти

- **Превью сразу, оригинал фоном.** Пока грузится полноразмерная картинка,
  показывается `/preview?w=800`; `src` подменяется, когда blob готов.
  Пользователь не видит пустоту ни кадра.
- **Кэш содержимого** (`src/lib/fileCache.ts`, 80 МБ, LRU). Повторное открытие —
  из памяти, без сети и без спиннера.
- **Предзагрузка соседей ±1** только для картинок и только без Save-Data: свайп
  становится мгновенным, а «на всякий случай» ничего не качается.
- **Один объектный URL на просмотр**, отзыв при закрытии/переключении; для
  скачивания — свой URL с отзывом через 60 с. Blob-URL никогда не передаётся в
  `window.open`.
- **Прогресс и спиннер** появляются только если загрузка длится дольше 300 мс.

### Ограничения

- Свайп влево/вправо между файлами есть только в режиме картинки; прочие типы
  по тапу скачиваются и в вьюер не открываются.

## Если что-то не работает

### Токен истёк (90 дней прошли)

Экран входа объясняет, что делать: войти заново логином и паролем БАРС. Токен
перевыпускается, данные не теряются — они в `data/users.json` на сервере.

### Ошибка входа в БАРС

Проверьте логин и пароль. Наличие привязки к Telegram не мешает входу в PWA;
бот и приложение используют одну запись пользователя.

### Обновление не подхватывается

Service Worker не даёт забрать старый бандл, пока пользователь в нём. Варианты:

- в приложении должен появиться тост «Доступно обновление» — нажать «Обновить»;
- один раз за сессию (чтобы не мельтешить перед глазами);
- вручную: DevTools → Application → Service Workers → «Update on reload»;
- полностью: DevTools → Application → Storage → «Clear site data».

### PWA не ставится на домашний экран

Чаще всего три причины, по убыванию частоты:

1. **Не HTTPS.** Safari не регистрирует Service Worker на `http://` — кроме
   `localhost`. Нужен реальный домен с сертификатом.
2. **Открыто в Chrome, а не в Safari.** На iPhone PWA ставится только из Safari.
3. **Нет иконки 512×512** в `manifest.webmanifest` либо `start_url` ведёт в
   никуда. Проверяется в DevTools → Application → Manifest.

### Кнопки «Открыть в браузере» нет в боте

Она появляется только при непустом `PWA_URL`. Проверьте, что переменная задана
**и что бот перезапущен** после её добавления.

### Расписание не обновляется, а данные из БАРС — да

Так и задумано: `/api/schedule` отдаётся stale-while-revalidate. Расписание
меняется раз в сутки, поэтому показ вчерашнего мгновенно лучше спиннера. Если
нужно принудительно — приложение умеет `?force=1`, или сбросьте Service Worker
в DevTools.

### Показывается `pwa_auth_disabled`

Не задан `PWA_AUTH_SECRET`. Сгенерировать: `npm run pwa:setup` (или
`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`), затем
перезапустить бот.

### «Слишком много попыток»

Сработал ограничитель входа: 5 неудачных попыток за 15 минут дают паузу, каждая
следующая блокировка удваивает её до потолка в 6 часов. Пауза видна на экране
входа, вместе с `retryAfterMs` — приложение показывает её до секунды.

## Что можно улучшить

- **`offline.html` без даты последнего обновления.** Сейчас страница говорит
  «нет сети» и предлагает повторить. Показывать «последнее обновление
  расписания: <дата>» упирается в то, что Cache Storage хранит только ответы;
  для даты пришлось бы класть её в заголовок ответа и читать при офлайне. Немного
  сложнее, чем кажется, и почти всегда не нужно.
- **Push-уведомления.** Сейчас офлайн ограничен показом последнего расписания.
  Полноценные пуши требуют отдельного сервиса и разрешения от iOS.
- **Кэш оценок с явной пометкой.** Сейчас оценки не кэшируются вовсе — это
  сознательный выбор (см. таблицу выше). Если захочется, потребуется маркировка
  ответа «данные на <дата>», иначе студент не отличит вчерашний день от сегодняшнего.

| `src/styles.css` | Подключение дизайн-системы из `src/index.css` |
| `src/lib/api.ts` | Клиент REST API: заголовок `X-PWA-Token`, файлы (загрузка, открытие, удаление) |
| `src/lib/env.ts` | Среда браузера: тема, вьюпорт, ссылки, отклик |

Клиент API в `src/lib/api.ts` — единственный в проекте, подменять его нечем.
Заголовок `X-PWA-Token` он шлёт всегда, когда токен есть: в отличие от подписи
Telegram, положить его «на всякий случай» в обычном браузере безвредно.
