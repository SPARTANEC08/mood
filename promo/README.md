# Mood — SMM-база

Редакционный конвейер: изменения → сценарий → пост и статья → утверждение →
публикация. Пост в Telegram публикует **только человек**. Статью в Telegraph
создаёт скрипт.

## Структура

```
promo/
├── config/       ссылки, бренд, ритм
├── brand/        тон, визуал, лого и QR
├── media/        видео, скрины, звук
├── motion/       политика, шаблон брифа, брифы
├── smm/          agent.md — инструкция агенту, правила, календарь
├── templates/    шаблоны сценария, поста, статьи
├── drafts/       черновики по датам (в git не идёт)
└── scripts/      сбор изменений, черновики, статья, отправка в бота
```

## Вечерний заход

```bash
cd promo

# 1. Коммиты за сегодня
npm run collect -- --date 2026-11-03

# 2. Написать drafts/2026-11-03/scenario.md
#    Формат: templates/scenario.md

# 3. Всё остальное одной командой
npm run finish -- --date 2026-11-03
```

`finish` делает по порядку:

1. собирает `telegram.md` и `telegraph.md`;
2. заливает новые скрины из `{{img:...}}` в GitHub Release;
3. публикует статью или обновляет её;
4. присылает в чат бота суммари и готовый пост с кликабельными ссылками.

Первый раз:

```bash
npm run tg:init   # нажать /start у @mood_mpei_bot перед запуском
```

Секреты лежат в `promo/.env` (в git не идёт):

- `TELEGRAPH_TOKEN` — создаётся сам при первой публикации;
- `TELEGRAM_CHAT_ID` — находит `tg:init`;
- `TELEGRAM_BOT_TOKEN` — берётся из корневого `.env`.

## Отдельные команды

```bash
npm run drafts  -- --date 2026-11-03   # только собрать тексты
npm run upload  -- --date 2026-11-03   # только скрины из сценария
npm run publish -- --date 2026-11-03   # создать статью
npm run publish -- --date 2026-11-03 --update
npm run send    -- --date 2026-11-03   # отправить в бота
npm run send    -- --date 2026-11-03 --dry-run
```

## На выходе

- `changes.md` — сырые пользовательские коммиты;
- `scenario.md` — сценарий;
- `telegram.md` / `telegram.html` — пост;
- `telegraph.md` / `telegraph.html` — статья и превью;
- `telegraph.json` — URL статьи;
- `assets.json` — локальный файл → URL в GitHub Release;
- `sent.json` — куда и когда ушёл пост.

## Правила

1. **Пост публикует человек.** Агент только присылает готовый текст.
2. **Статья — по эталону** `telegra.ph/Mood-obnovlenie-11-01`: ссылки сверху и
   снизу, дата, «Вот что нового.», жирные разделы с эмодзи, фото внутри,
   без видео и блока установки.
3. **Только пользовательские изменения.** Рефакторинг, тесты, docs, миграции и
   зависимости в дайджест не идут.
4. **Медиа не на проде.** Скрины — в GitHub Release, видео — только в Telegram.
5. **Motion только по ТЗ.** Без брифа в `motion/briefs/` не трогаем `src/`,
   `media/video/`, `media/audio/`.
6. **Ссылки и UTM** — из `config/links.json`; пустые не выводим.

## Что не коммитим

`public/`, `media/video/*.mp4`, `media/audio/*.wav`, `media/stock/*.png`,
`drafts/`, `.env`.

## Полезные файлы

- `smm/agent.md` — инструкция вечернему агенту (одна страница);
- `smm/changelog-rules.md` — что считать новостью;
- `smm/approval.md` — чек-лист перед публикацией;
- `brand/tone-of-voice.md` — как писать и как не звучать как ИИ;
- `brand/visual.md` — как выглядят скрины и видео.
