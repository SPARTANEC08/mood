# Zbot — полная техническая и функциональная документация

Telegram-бот для студентов НИУ МЭИ. Расписание, домашние задания, объявления группы
плюс личный кабинет БАРС МЭИ (оценки, пропуски, приказы, стипендия, библиотека) и корпоративная почта ОСЭП.

Документ описывает состояние кода на **09.10.2026**.

---

## 1. Назначение и границы

**Что делает бот:**
- показывает расписание группы с официального портала `ts.mpei.ru`;
- принимает домашние задания в свободной форме и привязывает их к будущей паре;
- хранит объявления группы («Важное») с файлами;
- по единой учётной записи МЭИ входит в личный кабинет БАРС и отдаёт успеваемость, пропуски, приказы, стипендию, книги НТБ;
- читает непрочитанные письма корпоративной почты ОСЭП (`mail.mpei.ru`);
- в фоне опрашивает БАРС и почту, присылая уведомления о новых баллах, письмах, приказах и смене стипендии.

**Чего бот не делает:**
- не входит в аккаунт напрямую через пароль в Telegram — пароль передаётся в чат один раз и сразу удаляется;
- не хранит файлы на диске: Telegram остаётся единственным хранилищем, сервер хранит только `file_id` и номера сообщений в канале.

## 2. Стек и архитектура

| Слой | Технология |
|---|---|
| Рантайм | Node.js 20+, TypeScript 5.6, ESM (`"type": "module"`) |
| Запуск TS | `tsx` (без предсборки), long polling grammY |
| Telegram | `grammy` ^1.46 |
| HTTP / scraping | `axios` + `axios-cookiejar-support` + `tough-cookie` + `cheerio` |
| Почта | `imapflow` (IMAP) + `mailparser` |
| Конфиг | `dotenv`, `.env` |
| Хранилище | локальные JSON-файлы с атомарной записью |
| Время | строго `Europe/Moscow` |

Проверка типов: `npm run lint` (`tsc --noEmit`), на момент документирования проходит без ошибок.
`tsconfig.json`: `strict: true`, `noEmit`, `moduleResolution: bundler`, `allowImportingTsExtensions`.
Из-за смешанных расширений импорта в коде одновременно встречаются `.ts`, `.js` и `.mjs` — причина в разнице ESM-резолвинга между `tsx` и `tsc`.

**Внешние сервисы:**

| Сервис | Адрес | Назначение |
|---|---|---|
| РУЗ / расписание МЭИ | `https://ts.mpei.ru/api` | поиск группы, выгрузка расписания |
| Личный кабинет БАРС | `https://bars.mpei.ru/bars_web/` | авторизация, оценки, пропуски, приказы, стипендия, НТБ |
| Почта ОСЭП | `mail.mpei.ru:993` (IMAPS) | письма МЭИ |
| Канал-хранилище | закрытый канал Telegram | хранение прикреплённых файлов |

## 4. Концепция интерфейса

### 4.1 Single-Message UI
Весь интерфейс живёт в **одном** сообщении бота, которое редактируется на каждом шаге:

1. ID главного сообщения хранится в `users.json` (`mainMessageId`).
2. Экран строится как `{ text, keyboard }`, отправляется через `editMessageText` в HTML-режиме.
3. Если сообщение удалено руками или правка невозможна — бот удаляет старое и шлёт новое, запоминая новый ID.
4. **Любое входящее сообщение удаляется** (`ctx.deleteMessage()`) — чат остаётся чистым. Сначала публикуется в канал-хранилище, потом удаляется: обратный порядок ломает `copyMessage` для альбомов.
5. Временные файлы карточек (`filesToSend`) отправляются отдельными сообщениями, их ID пишутся в `transientMessageIds` и удаляются при следующем действии.
6. Нижняя `reply_keyboard` (одна кнопка `⚙️ Остальное`) инициализируется один раз после успешного входа; служебное сообщение «Инициализация меню…» сразу удаляется.
7. Фоновые уведомления, наоборот, приходят **новым** сообщением, чтобы не перетирать навигацию.

### 4.2 Форматирование (`format.ts`)
- Весь текст — HTML: `<b>`, `<i>`, `<code>`, `<blockquote>`, `<blockquote expandable>` (сворачиваемые блоки).
- Любой пользовательский текст проходит `esc()`; теги из данных не «текут» в разметку.
- Смысловые тоны кнопок (`Tone`) отображаются в три цвета Telegram: `primary` (синий), `success` (зелёный), `danger` (красный). Лекции — синие, практики — красные, лабораторные — синие, обед — зелёный, красный закреплён за «назад» и «выйти».
- `RULE` — разделитель из 12 символов `━`, склеенных неразрывным WORD JOINER (U+2060): символ занимает две ячейки, поэтому на узком экране линия переносилась и ломала вёрстку.
- `fmtNum` печатает баллы как «4,5», `plural` склоняет существительные, `truncate` режет длинные строки.

## 5. Авторизация в БАРС МЭИ

### 5.1 Воронка (`botEngine.handleLoginInput` → `handlePasswordInput` → `handleTwoFactorInput`)

Шаг 0. **Гейт.** Любой текст и любой callback от неавторизованного пользователя возвращают экран входа
(`isBarsAuthorized` требует `barsAuth` + `studentProfile.fullName`).

Шаг 1. **Логин.** Обычный текст (`/start` отбрасывается). Сохраняется `authState: 'AWAIT_PASSWORD'` и `tempAuthData.login`.
Пароль в `users.json` на этом шаге **не пишется**.

Шаг 2. **Пароль.** `startBarsLogin()` уходит в фон, экран показывает «Подключение к БАРС МЭИ…».
Пароль живёт только в памяти до конца авторизации; на диск попадает исключительно зашифрованный.

Шаг 3. **2FA.** Парсер страницы достаёт параметры `af2_code_send(...)`: id кнопки, относительный URL, `tid`, длину кода и текст канала.
Бот **сам** вызывает `GET .../JSON_SendAF2_Code?tid=N` — в браузере это делает JS, а axios/cheerio его не выполняют, без ручного вызова код просто не придёт.
Затем бот просит код у пользователя и ждёт до 5 минут (`TWO_FA_TIMEOUT_MS`), затем `POST`ит код на `/bars_web/Auth/LoginCode`.

Финал. `finalizeRegistration()`:
- извлекает ФИО, номер зачётной книжки (`№ЗК`), группу из ЛК;
- `searchGroupOnMpei()` находит `groupId` на `ts.mpei.ru` по названию группы из БАРС;
- шифрует логин и пароль AES-256-GCM (раздельно, свой IV и tag у каждого);
- сохраняет куки сессии и `finalUrl`;
- через `emit()` обновляет главное сообщение — асинхронный канал доставки (`AuthFlowListener`), который регистрирует `telegramService`.

Ошибки обрабатываются по тексту (`handleAuthFailure`): неверные креды → на ввод логина; неверный код 2FA → сессия БАРС непригодна, тоже на ввод логина; не введён код → сброс воронки.

### 5.2 Сессия на диске
Сессия — это `cookiesJson` (JSON кук tough-cookie + `finalUrl`). `loadSavedSession()` умеет читать только файл,
поэтому `createBarsServiceForUser()` кладёт расшифрованные данные во временный файл в `os.tmpdir()` и **сразу удаляет** его.
На диске остаются только зашифрованные значения.

### 5.3 Контроль живости сессии
`BarsClient.assertSessionAlive()` бросает `SessionExpiredError`, если URL содержит `/auth/login`, `/auth/logincode`, `returnurl=`,
или в разметке есть поля `Password` / `AF2_Code`, или заголовок говорит про авторизацию.
В `botEngine.handleServiceCallback` это приводит к сбросу авторизации и возврату на экран входа;
в нотификаторе — к `userStore.clearAuth()` + удалению снимка.

## 6. Расписание МЭИ

### 6.1 Поиск группы (`mpeiApi.searchGroupOnMpei`)
- `GET /api/search?term={query}&type=group`.
- Нормализация: пробелы, длинные тире → дефис.
- Fallback: латинские look-alike буквы конвертируются в кириллицу (`C→С`, `A→А`, `E→Е`, `H→Н`, `K→К`, `M→М`, `O→О`, `P→Р`, `T→Т`, `X→Х`, `Y→У`).
- Матчинг: точное совпадение без учёта регистра; единственный результат; совпадение после удаления пунктуации. Иначе — подсказки.

### 6.2 Загрузка и кэш
- `GET /api/schedule/group/{groupId}?start=YYYY.MM.DD&finish=YYYY.MM.DD&lng=1`.
- Окно: **−14 дней … +90 дней** — этого хватает, чтобы всегда найти будущую пару для ДЗ.
- Кэш в памяти `botEngine.scheduleCache`, TTL **3 минуты**, ключ `group_{groupId}`; чистится кнопкой «Обновить», командой `/reflash`, кнопкой меню и обновлением сессии.

### 6.3 Структура (`scheduleParser.parseSchedule`)
Сырые записи сортируются по дате → номеру пары → времени → подгруппе, затем:
1. группируются по `date` (`rawDate` = `YYYY.MM.DD`);
2. внутри дня — по ключу слота `lessonNumberStart_beginLesson_endLesson`;
3. подгруппы, потоки, объединённые группы, аудитории, ФИО и звания преподавателей, ссылки на онлайн-занятия становятся `variants` слота.

Результат: `ParsedSchedule { days: ParsedScheduleDay[] }`, где день содержит отсортированные `slots`.

### 6.4 Главный экран (`buildMainScheduleView`)
- Шапка: `📅 06.10.2026 (Вторник)` + строка `👤 Лысенко Н.Р. │ ИЭ-11-26`.
- Список пар — **только кнопками**, текст не дублирует клавиатуру.
- Кнопка пары: иконка типа, время начала и конца, короткое имя дисциплины, короткий тип, аудитория, значок `📝` при наличии ДЗ.
- Цвет по типу: лекция — `📘 л`, практика/семинар — `📙 п`, лабораторная — `🧪 лаб`, прочее — `📍 зан`.
- Кнопка `🥪 12:45–13:45 Обед` вставляется перед 3-й парой (или после последней, если пар меньше трёх). По клику — popup-алерт со случайной фразой без навигации.
- Навигация: `[◀️ Пн] [🗓 Сегодня] [Ср ▶️]`, затем `[📊 Оценки] [📬 ОСЭП]`, затем `[⚙️ Остальное]`.
- Если день не найден — берётся сегодняшний, иначе ближайший будущий, иначе первый день.

### 6.5 Сокращение дисциплин (`formatDisciplineShortName`)
Словарь из ~45 правил, чтобы кнопки не обрезались: ОРГ, ОПД, БЖД, Физ-ра, Иняз, Матан, Линал, Диффуры, Тервер, Дискретка, Информатика, Прога, АВС, БД, ОС, Сети, ТОЭ, Электротех., Инжграф, Материалы, Метрология, Сопромат, Термех, ЭМПВ, Электродин., История, Социология, Право, Философия, Экономика, Практика.
Всё, что длиннее 13 символов и не распознано, режется по первому слову.

## 7. Домашние задания

### 7.1 Формат ввода
```text
предмет л/п/лаб текст задания
```
Пример: `Матан п №1-5 стр. 20`. Можно прикрепить файлы (тогда текст необязателен).
Команда `/dz` без содержимого показывает инструкцию.

Регулярка `HW_REGEX` принимает маркеры `л|лек|лекция|п|пр|практика|сем|семинар|лаб|лаба|лабораторная`.

### 7.2 Резолвинг предмета (`subjectAliases.resolveDisciplines`)
Каскад: точное совпадение → словарь алиасов (в т.ч. по префиксу при длине ≥ 3) → аббревиатура по первым буквам значимых слов (`Основы российской государственности` → `орг`) → префикс названия или любого слова.
Результат — **точные официальные названия из расписания**. Если предмет не найден, пользователю выводится список предметов группы.

### 7.3 Привязка к паре (`findNextLesson`)
- Время всегда приводится к Москве.
- Дни с `rawDate <= сегодня` пропускаются целиком: ДЗ всегда цепляется к **следующей** паре этого предмета в будущем дне.
- Типы разделены строго: `л` — только лекции, `лаб` — только лабораторные, `п` — всё, что не лекция и не лабораторная, кроме экзаменов, консультаций, зачётов, аттестаций.
- Если подходящей пары нет — ДЗ не сохраняется, выводится понятная ошибка («Не нашёл будущих практик по предмету …»).

### 7.4 Просмотр
- `📖 ДЗ` (`nav_dz`) — список записей группы начиная с сегодняшнего дня, сортировка по дате и номеру пары.
- Карточка ДЗ (`hw_detail:<id>`) — дисциплина, тип, дата, пара и время, автор, текст, файлы; кнопка `🗑 Удалить ДЗ`.
- ДЗ показывается и в карточке пары (`sub:<rawDate>:<index>`) — там же кнопки удаления каждого задания.

### 7.5 Удаление
`hw_del_ask:<id>` → экран подтверждения → `hw_del_confirm:<id>`. Запись удаляется из `data/homework.json`,
все её `channelMessageIds` удаляются из канала-хранилища, пользователь получает тост `ДЗ удалено`.

## 8. «Важное» (объявления группы)

- Список (`nav_important`) — новые сверху, значок `📎` при наличии файлов, кнопка `➕ Добавить объявление`.
- `imp_add` переводит пользователя в режим ожидания текста (`waitingForImportantText`); первая строка (до 35 символов) становится заголовком, текст — содержимым, файлы прикрепляются к записи.
- `отмена` выходит из режима без сохранения.
- Карточка `imp:<id>` — заголовок, текст в цитате, автор, количество файлов; удаление через подтверждение `imp_del_ask` / `imp_del_confirm` с чисткой канала.

## 9. Сервисы личного кабинета

### 9.1 Хаб «Остальное» (`buildMoreHubView`)
```
📖 Домашние задания      ⭐ Важное
📉 Пропуски              📚 Книги (НТБ)
📜 Приказы и стипендия    🔄 Обновить сессию
🚪 Выйти из аккаунта БАРС
◀️ Назад к расписанию
```
«Оценки» и «ОСЭП» висят прямо в главном меню расписания; остальные — в «Остальном».
Кнопка «назад» ведёт туда, откуда раздел открыт, — это сделано явно в `moreView.backRow`.

### 9.2 Оценки (`svc_grades` → `gradesParser` + `gradeCalculator`)
- Страница: `/bars_web/ST_Study/Main/Main` (или `finalUrl` сессии).
- `controlPoints` — настоящие КМ с весами в процентах (сумма по дисциплине = 100), `weekScores` — контрольные недели отдельно.
- Тип аттестации нормализуется в `Зачет | Диф. зачет | Экзамен | Неизвестно`.
- `weightedAverage` считает средневзвешенный балл только по КМ с выставленной оценкой; если весов нет — обычное среднее. Результат округляется до двух знаков и печатается как «4,5».
- Экран: дисциплины, отсортированные от худшего среднего к лучшему; значок среднего (`🟢 ≥4,5`, `🟡 ≥3,5`, `🟠 ≥2,5`, `🔴` иначе), итоговая оценка из ЛК, сворачиваемый блок КМ с весами и неделями, счётчик «Закрыто N из M КМ».

### 9.3 Пропуски (`svc_attendance` → `attendanceParser`)
- Страница: `/bars_web/ST_Study/Main/Summary?studentID=...`.
- **Важно:** БАРС отдаёт количество **занятий**, а не часов; 1 пара = 2 акад. часа (`ACADEMIC_HOURS_PER_LESSON`).
- Экран показывает и пары, и часы, с разбивкой на уважительные и неуважительные, сгруппированно по дисциплинам; если пропусков нет — 🎉.

### 9.4 Книги НТБ (`svc_library`)
`/bars_web/ST_LIB/BookCopy/ListStudent__BookCopy` → список книг, просроченные помечаются ⚠️, срок сдачи выводится явно.

### 9.5 Приказы и стипендия (`svc_orders`)
Параллельно грузятся `/ST_LK/Order/ListStudent__Order` и `/ST_LK/ScholarshipEvent/ListStudent__ScholarshipEvent`.
Показываются первые 8 приказов со счётчиком «Показаны первые 8 из N» и статус стипендии.

### 9.6 ОСЭП (`svc_osep`)
Отдельная ветка: креды берутся из расшифрованных логина и пароля БАРС (единая учётная запись) — повторный вход не нужен.
`OsepMailClient` подключается к `mail.mpei.ru:993` по TLS, логин без `@mpei.ru` (Exchange), при отказе — повтор с полным адресом.
Показываются непрочитанные письма (до 8) с отправителем и превью на 110 символов.

### 9.7 Управление сессией
- `auth_refresh_session` — проверка живости сессии; при успехе обновляет `barsAuthedAt`, чистит кэш расписания и перерисовывает меню; при неудаче возвращает на вход.
- `auth_logout` — `userStore.clearAuth()` удаляет `barsAuth`, `studentProfile`, `barsAuthedAt` и сбрасывает воронку.
- `auth_restart` — сброс воронки без удаления данных.

## 10. Файлы и канал-хранилище

Файлы **не хранятся на диске**. Сервер держит только `fileId`, `fileUniqueId`, имя, размер, mime и `channelMessageId`.

### 10.1 Публикация
1. Бот формирует заглавный пост: `📚 #ДЗ #ИЭ_11_26` + группа, предмет и тип, дата и номер пары, текст задания, автор (для объявлений — `📌 #Важное #<группа>`).
2. Файлы: сначала пробуется `copyMessage` входящего сообщения целиком (надёжный перенос альбома), при неудаче — отправка по одному с `reply_to_message_id` на заглавный пост.
3. Все ID (заголовок + файлы) пишутся в `channelMessageIds`; в записи остаются только успешно сохранённые файлы.
4. Если канал недоступен или файл не лег — запись сохраняется без файлов, а пользователь получает честное предупреждение: файл живёт только в Telegram, прикреплять нужно заново. Ссылка на несуществующий файл в базе бесполезна.

### 10.2 Выдача пользователю
Тип определяется по сохранённому полю `type`, иначе по префиксу `file_id` (`Ag` → photo, `BQ` → document, `BA` → video, `CQ` → audio, `Aw` → voice).
Метод подбирается по типу; при отказе делается повтор через `sendDocument`, а для типа `document` дополнительно перебираются photo/video/audio.
Ошибки вида `wrong file identifier` прерывают перебор сразу. Если файл не отправился ни одним способом, пользователь об этом сообщает явно.
ID отправленных файлов сохраняются как временные и удаляются при следующем действии.

### 10.3 Подводный камень Telegram
`file_id` привязан к конкретному боту. Если база переносилась с другого бота, все старые `file_id` становятся мёртвыми. Для проверки есть `npm run check:files`.

### 11.6 Шифрование (`utils/crypto.ts`)
AES-256-GCM, ключ из `ENCRYPTION_SECRET_KEY`: 64 hex-символа либо произвольная строка ровно 32 байта UTF-8.
IV — случайные 12 байт на каждое шифрование, tag — 16 байт, хранятся отдельно.
**Логин и пароль шифруются раздельно** (у каждого свой IV/tag): повторное использование пары (ключ, IV) в GCM раскрывает XOR ключевого потока и делает аутентификацию небезопасной.
При неверной длине ключа бросается `EncryptionConfigError` — но только в момент реального шифрования, чтобы бот запускался и без секрета.
Генерация ключа: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.

## 12. Фоновые уведомления (`barsNotifier.ts`)

### 12.1 Режим
- Цикл каждые **20 минут**, первый прогон через 30 секунд после старта.
- Активное окно **08:00–23:00 МСК**; ночью воркер спит, а круг, начавшийся в 22:59, прерывается при закрытии окна.
- Обход пользователей **строго последовательный** с паузой 2500 мс + случайный джиттер до 500 мс — иначе МЭИ банит по IP.
- Таймаут на пользователя — 60 секунд; **5 сетевых сбоев подряд** прерывают весь круг, чтобы не «высасывать» всех студентов при лежащем сервере.
- `isCycleRunning` защищает от наложения циклов; таймер `unref()`, чтобы не удерживать процесс.

### 12.2 Снимки и диффы
`collectState()` грузит оценки, приказы и стипендию параллельно через `Promise.allSettled`; падение одного блока не обнуляет остальные.
Если БАРС недоступен целиком — это считается сетевой ошибкой и снимок **не обновляется**.
Почта ОСЭП — отдельный блок: сбой IMAP не влияет на остальное.

`diffSnapshots()` формирует события:
- **grade** — изменился балл по КМ (показывается дельта `+7`);
- **mail** — `lastSeenMailUid` вырос (до 5 последних писем);
- **order** — количество приказов увеличилось;
- **scholarship** — сменился нормализованный статус стипендии.

Первый снимок — базовая линия: уведомления не отправляются, только сохраняются.
Снимок обновляется всегда, даже если отправка не удалась, чтобы не слать одно и то же повторно.
Сервис не знает про grammY: получателем является функция `NotificationSender`, которую регистрирует `telegramService`.

## 16. Известные риски и техдолг

1. **Хардкод токена в `52.py` и `67.py`** — эксперименты на aiogram лежат в корне с реальным токеном бота в открытом виде. Токен нужно отозвать через @BotFather и удалить эти файлы из репозитория; `.gitignore` в проекте отсутствует, а `.env`, `.bars-session-debug.json` и `.bars-debug-*.html` тоже содержат секреты — риск утечки при первом же `git add`.
2. **`.bars-session-debug.json` и HTML-дампы** содержат живые куки и персональные данные ЛК. `barsAuth.ts` по умолчанию пишет сессию в этот файл, если не задан `saveSessionPath`; в боевом пути это переопределяется временным файлом, но при ручных запусках дамп остаётся на диске.
3. **Хрупкость скрапинга БАРС** — парсеры привязаны к HTML конкретной версии ЛК. Любая смена вёрстки молча даёт пустые разделы; `isDashboardPage` и `assertSessionAlive` используют набор эвристик, которые со временем потребуют обновления.
4. **Кэш расписания в памяти на 3 минуты** не переживает рестарт процесса — на нескольких инстансах у каждого своя копия.
5. **Нет шины событий и очередей**: `scheduleCache`, `pending2FA`, `loginInFlight`, `waitingForImportantText`, `transientMessageIds` живут в памяти процесса. При горизонтальном масштабировании состояние разъедется.
6. **`data/*.json` без миграций и версионирования схемы.** `readBarsCredentials()` уже содержит fallback на старый формат `iv`/`tag` для пароля — это ручной миграционный код, который со временем стоит заменить на явные миграции.
7. **Один `JsonStore` на файл без блокировок** — параллельные записи возможны при нескольких процессах; атомарность гарантируется только в пределах одного процесса.
8. **Нет автотестов в привычном смысле** — нет CI, нет jest/vitest, нет покрытия; smoke-скрипты запускаются вручную.
9. **Оценки считаются по КМ с весами**, тогда как итоговый балл БАРС может считаться иначе; в экране рядом показываются оба, но расхождение возможно.
10. **`quality`-независимый парсинг пропусков**: пересчёт «пара = 2 часа» зашит в константу; если в МЭИ появятся занятия другой длительности, счётчик разойдётся с ЛК.
